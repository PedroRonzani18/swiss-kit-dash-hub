# Swiss Kit Pipeline

This directory stores handoff artifacts for Codex-assisted development runs.

The goal is not to let AI code freely. The goal is to keep planning, implementation and review separated and auditable.

## Structure

```text
.pipeline/
  README.md
  runs/
    <run-id>/
      request.md
      context.md
      spec.md
      changes.md
      test-results.md
      review.md
      state.json
```

## Files

### `request.md`

Original user request.

### `context.md`

Repository context found by the Planner:

- relevant files
- existing patterns
- commands
- architecture notes
- risks

### `spec.md`

Implementation spec generated by the Planner.

Must include:

- objective
- in scope
- out of scope
- files likely to change
- acceptance criteria
- edge cases
- validation commands
- risks
- open questions, if any

### `changes.md`

Implementation summary generated by the Coder.

Must include:

- files changed
- behavior changed
- tests added or updated
- validation commands
- known risks

### `test-results.md`

Optional in the MVP.

Used when a separate Tester stage is added.

### `review.md`

Read-only review generated by the Reviewer.

Must end with:

- `VERDICT: SHIP`
- `VERDICT: NEEDS WORK`
- `VERDICT: BLOCK`

## Git policy

Generated run folders should not be committed.

Keep only:

```text
.pipeline/README.md
.pipeline/runs/.gitkeep
```

Ignore:

```text
.pipeline/runs/*
!.pipeline/runs/.gitkeep
```

## Human approval

The pipeline does not approve its own work.

A human must review the diff and decide whether to commit, push or merge.
